Roblox's setup requirements are documented at https://create.roblox.com/docs/cloud-services/data-stores.

`WorldService` restores the complete exchange before it accepts orders: candles and cumulative volume, last executed prices, live FIFO orders and partial quantities, player balances and positions, armed/triggered SL/TP, bot capital and inventory, pending whale slices, participant deadlines, beliefs, regime/news state and the RNG's exact next draw. Warmup and the opening auction only run for a new world. Disconnecting cancels that player's working orders but keeps positions, balances, and protective triggers. Offline protective exits may consume available liquidity; they cannot leave disconnected resting liquidity in the book. There is currently no automatic daily loss-limit reset.

The shared exchange uses **one active Roblox server**, protected by an atomic DataStore writer lease. Other public servers route arrivals into that server with `TeleportAsync`. Private servers act as entry lobbies and cannot own the public exchange. Players therefore use the same book, prices and execution stream. Studio cannot perform cross-server teleports; if another Studio test owns the Studio lease, stop it first. A full or temporarily unreachable exchange remains in a connecting state and retries instead of generating another market. **Capacity is one Roblox server**; supporting many full trading servers would require a separate exchange transport/backend. Real teleport behavior must be verified after publishing.

Checkpoints save every 15 real seconds and on normal shutdown. Market and account state share one compressed, checksummed checkpoint so fills cannot restore against different balances. Its lease lasts 90 seconds with a 15-second safety margin. Storage failures pause trading; an expired or superseded server cannot trade or overwrite the new owner's state. Corrupt, missing or incompatible saved checkpoints fail closed, without reseeding. Shutdown freezes execution, flushes the checkpoint and releases ownership. An abrupt crash can lose trades since the last successful checkpoint, normally up to 15 seconds, and recovery may wait for the lease to expire. This is checkpoint durability, not a transaction journal for every fill.

When no Roblox server is running, simulation time pauses. The next owner resumes the saved market; it does not invent candles or silently simulate trades during offline time. An external always-running service would be needed for 24/7 execution with zero players. Rendering cadence remains unchanged; `SimulationSpeed = 18` produces one-minute simulated candles in approximately 3.33 real seconds. See [the E-mini update report](PROGRESSION_EMINI_UPDATE.md) for current migration, loss rules and measured performance.

Server-only settings are in `ServerScriptService.MarketReign.WorldConfig`. Keep `Enabled=true` in published games. `StoreName`/`WorldKey` select the durable world; changing either deliberately starts a separate world. `StudioReplaySeed` can reproduce a *new* Studio world for debugging, but does not replace an existing checkpoint. Live worlds always start with a private generated seed. No seed, bot belief, checkpoint or future RNG state is replicated to players. Stored behavior settings remain attached to that world; cadence/speed can change, but instruments, ticks and timeframes require an explicit migration. The encoded-size guard pauses before exceeding storage capacity; old player accounts are not silently deleted to make room.

## Configuration

Edit `ReplicatedStorage.MarketReign.MarketConfig` in Studio (`src/MarketConfig.luau` is the source copy).

- `Seed` in this shared configuration is for offline preview/tests only. Runtime seeds and replay settings stay server-only; see `WorldConfig` above.
- The default population is 147 participants across BX, BT and BG: 36 ordinary traders, 10 makers and 3 whales per instrument. Older worlds can also retain retired books and their existing participants for outstanding exposure.
- `MakerPopulationVersion = 1` upgrades older saved worlds to at least 10 makers per active market on restore. Existing participants, accounts, resting orders and candle history are preserved. New makers start on future scheduler steps; restoring does not submit their quotes or print trades. Retired markets are excluded, renamed participant ids remain intact, and subsequent restores add no duplicates. This migration runs when a server starts the updated build; an already-running server must restart to adopt it.
- `ParticipantsPerInstrument`, `MakersPerInstrument`, `WhalesPerInstrument`, `BehaviorWeights`, `Liquidity`, `Volatility`, `WhaleFrequency`, `NewsFrequency` and weighted `Regimes` control behavior. A zero whale frequency disables whales.
- `SimulationSpeed = 18` advances eighteen simulated seconds per real second. `StepSeconds = 0.25` is the deterministic scheduler interval, producing 72 scheduler steps per real second. Volatility remains unchanged at 1.
- `WarmupSeconds = 1800` generates 30 simulated minutes of actual trades before clients connect. Larger timeframes initially have fewer candles; there is no fabricated daily history.
- Candles retain 720 buckets per timeframe. Trades and completed orders retain 4,000 records each; cumulative audit totals remain available after old records expire.
- `Margin` values are configurable simulated margin requirements, not broker margin quotes.

## Runtime layout

| Module | Location | Purpose |
| --- | --- | --- |
| MarketEngine | ServerScriptService.MarketReign | Tick-based order books, matching, account settlement, risk, protection and trade-derived candles |
| Participants | ServerScriptService.MarketReign | Seeded participants, finite capital, maker quotes, whale execution, regimes and news |
| MarketServer | ServerScriptService.MarketReign | Central Heartbeat scheduler, validated request queue, deduplication, rate limits and batched updates |
| MarketTests | ServerScriptService.MarketReign | Reproducible engine regression suite |
| WorldConfig / WorldService | ServerScriptService.MarketReign | Storage configuration, restore/save lifecycle, fail-closed trading and exchange ownership |
| WorldLease / WorldCheckpoint | ServerScriptService.MarketReign | Atomic ownership fencing, compressed durable engine/participant state |
| WorldTests | ServerScriptService.MarketReign | Continuity, codec, ownership, restoration and outage regression suite |
| MarketClient | ReplicatedStorage.MarketReign | Read-only snapshot cache and order requests |
| TerminalUI | ReplicatedStorage.MarketReign | Existing responsive desktop/mobile interface |

Market orders use available liquidity and cancel any unfilled remainder. Marketable limits fill only at their price or better, then rest. Players and automated participants now match in the same finite book; player executions change the tape, candles, and both counterparties' balances and positions. Resting orders use price priority followed by arrival priority. Changing a limit's price preserves its identity and protection but loses time priority; a no-op price amendment keeps it. Self trades across the same owner/profile cancel the older quote instead of generating volume. Cancelling one account's orders cannot affect another account.

Stops and profit targets are reduce-only, mutually exclusive closing triggers. They latch on each executed trade and cancel related working entries. Stop-loss, manual close, and liquidation consume real available liquidity and retry unfilled protective residuals on later scheduler steps. A triggered take-profit submits a limit at the target, retains its queue priority while resting, and cannot fill at a worse price. Neither kind guarantees a complete fill; stops can slip. Position entry is the weighted average of actual fills; adding in the same direction updates attached distances from that average. Closing cancels entries and retries a residual position without reversing it.

Checkpoint V9 persists the shared book and amendment priority. On migration from V1–V8, old off-book player limits are cancelled rather than retroactively matched; balances, positions, protective triggers, and existing tape are preserved. Runtime connection state is rebuilt from actual connected players before the exchange advances. The historical house ledger remains only for trusted administrative migration/reset settlement; ordinary player orders cannot use it.

## Level 2 market depth

L2 is inside the trade panel below Take profit, with Buy/Sell pinned outside the scrolling fields. Expanded height is 322 pixels for the engine's current five levels per side, with fixed 22-pixel rows and fixed columns; collapse uses 40 pixels. Best ask and best bid stay adjacent to the spread. Missing levels remain blank, with explicit empty/missing/stale states. Quote updates reuse row objects; order/position updates retain the trade ticket, unfinished text, and scrolling. The old liquidity-source labels and redundant empty-position helpers are removed.

Each price sums actual remaining executable quantity, anonymously combining connected players and automated participants. Armed stops and invalid, expired, filled, or cancelled orders are excluded. Both sides use one labelled per-instrument quantity scale that grows in powers of two only when required; removing a large order does not resize every other bar. There are no padded levels or fabricated signals.

Maker policy V2 preserves resting quotes and partial quantities between material changes. Normal repricing requires at least 18 simulated seconds of rest (one real second at speed 18) and a move of at least three ticks, or a change in eligible quoting depth. Risk withdrawal remains immediate. Quotes expire after 108 simulated seconds; consumed quotes have a replenishment delay. Independent random quote-center/width jitter is removed. Other participants cancel only mature stale orders instead of clearing all orders at random decision points. Simulation speed and honest execution quantities are unchanged.

Futures balance equals starting funds plus realized P&L; equity adds marked unrealized P&L. Margin reserves worst-case directional exposure from positions and working orders. A separate notional cash-flow ledger checks that transfers cancel across accounts. Fees are not modeled. Practice accounts are separate server-owned accounts; switching does not pause the other account or its protection.

Clients receive quotes and the latest two candle buckets every 0.1 seconds (10 Hz), with a full selected-series snapshot on subscription. Unchanged orders, fills and trade history are omitted from subsequent batches; the client retains them until a changed snapshot arrives. Protective order status is compared separately so an OCO trigger is transmitted even before its closing fill. Depth is sent only for the selected instrument. Client rendering preserves order controls, focus and scroll positions between price updates. The chart requests 72 bars on desktop and 36 on mobile, clamped to viewport width and retained history; zoom has a 10-bar minimum and a 1,000-bar rendering ceiling.

## Chart navigation

In Play mode, drag the chart with the mouse or one finger to pan through time and price. Pan (the double arrow) is selected by default; dragging also works with Crosshair selected. The mouse wheel zooms around the time under the pointer. **Go live** restores the latest candles and automatic price scaling. Each instrument/timeframe remembers its own view.

The market continues executing while the chart is panned. New snapshots do not move the selected time or price range. Trend drawings are anchored to time and price and move with the chart. Select the line or trend tool for drawing; select Pan again to move the view. Middle-button dragging also pans while a drawing tool is selected.

The input surface survives market updates, and chart marks are reused from a bounded pool during drags rather than destroyed and recreated. The saved Edit preview remains a static authoring preview; interactive controls run in Play mode.

Navigation paints once per display frame when input changes, without the former 30 Hz limiter. The pool caches unchanged properties, moves each dashed line as one group, and retains the footer. Incoming candle geometry settles over an 80 ms visual transition, disabled during navigation so the chart follows the pointer immediately. Quotes, OHLCV, stops, targets and P&L always use the server's exact values; animation never modifies candle data. SimulationSpeed is 18.

## Replay and validation

Reproducibility is defined by seed, configuration, and the same account actions at the same simulation steps in the same order. Wall-clock delays are not replay coordinates. The central scheduler does not skip steps when catching up. `MarketTests` compares the complete execution tape between two seeded runs with identical step-indexed player actions and checks that another seed produces a different result.

In Play mode, use the **server** command context:

```lua
local diagnostics = game.ServerScriptService.MarketReign.StudioDiagnostics
print(diagnostics:Invoke("Tests")) -- Passed = 11, Total = 11
print(diagnostics:Invoke("Audit")) -- live conservation, book and account snapshots
print(diagnostics:Invoke("Actions")) -- latest 5,000 accepted player requests with step and sequence
print(diagnostics:Invoke("ContinuityTests")) -- six checks using isolated simulated storage
```

The diagnostics object exists only in Studio and is never replicated to clients. The action log is a debugging window, not persistent session storage.

## Dragging position protection

In Play mode, drag an armed SL or TP line, its label, or its price-axis tag with mouse or touch. The arrow marks editable protection. The proposed price and projected P&L snap to the contract's tick size. Release submits one server request; the original protection remains armed until the server accepts. The chart scale stays fixed during the gesture and acknowledgement. Escape, loss of window focus, a cancelled touch, or a closed/changed position cancels the gesture. Drag elsewhere to pan; middle mouse always pans.

The server checks ownership, position identity, the previous protection price, tick alignment, price band, current trade price, triggered status and remaining loss allowance. Stops can move past entry to protect profits while remaining on the correct side of the current market. Rejected changes restore the last server state. Moving a line does not create trades, candles, cash or P&L; subsequent actual executions still trigger the protective exit and OCO handling.

Desktop and 390×844 Play viewport tests dragged both protections, checked tick snapping, frozen chart bounds, unchanged armed prices before release, and server acknowledgement. Long and short amended stops/targets, profitable stops, stale/foreign requests, risk rejection and resulting fills pass in the engine suite. Touch uses the same input path with larger hit targets; physical-device touch was not tested. Studio's virtual-input API reserves Escape for CoreGui, so automated Escape injection could not verify that shortcut.
